### Calibration pipeline

```bash
npm run calibrate                 # Full pipeline (download → extract → merge → analyze → generate)
npm run calibrate:analyze         # Re-run analysis against existing registry (fast)
npm run calibrate:generate        # Regenerate weight-overrides.json from analysis.json
npm run calibrate:dictionary      # Regenerate dictionary.json from registry.json
npm run calibrate:prune           # Prune dictionary entries the algorithm now handles
npm run calibrate:discover        # Find missing romanization variants from close matches
```

## Architecture

```
Thai Text → segmentWords() → parseSyllables() → romanizeSyllable()
          → generateVariants() → dictionaryMerge() → combineWordVariants() → Results
```

- **`src/index.js`** — public API entry point; `transliterate()`, `transliterateVariants()`, `transliterateWords()`, `matchThai()`
- **`src/syllable-parser.js`** — state machine that splits Thai text into structured syllable objects (initial consonant, vowel, final consonant, tone markers)
- **`src/romanizer.js`** — maps each syllable's parts to weighted variant arrays via the tables
- **`src/variant-generator.js`** — Cartesian product of per-position variants with weight-based pruning (`MAX_PER_SYLLABLE=8`, `MAX_INTERMEDIATE=50`) and deduplication
- **`src/dictionary.js`** — lazy-loaded lookup that merges `dictionary.json` (auto-generated) and `dictionary-manual.json` (hand-curated); manual always wins on collision

### Table layer (`src/tables/`)

- **`consonants.js` / `vowels.js` / `clusters.js`** — base RTGS mappings with weights; contain only linguistic fact, no empirical tuning
- **`load-weights.js`** — merges base tables with `weight-overrides.json` at runtime; all romanizer/syllable-parser imports go through here
- **`weight-overrides.json`** — data-derived weight adjustments + `newVariants` section for romanizations not in the base tables; regenerated by `calibrate`
- **`dictionary.json`** — ~558 entries where the algorithm still gets the wrong top-1 result; regenerated by `calibrate:dictionary`
- **`dictionary-manual.json`** — hand-edited translations (Bangkok, Thailand) with hardcoded weight 1.5; never overwritten by calibrate

### Weight priority at runtime

| Source | Weight range | Wins over |
|--------|-------------|-----------|
| `dictionary-manual.json` | 1.5 (hardcoded) | everything |
| `dictionary.json` (≥10 observations) | 1.1 | algorithm |
| `dictionary.json` (≥5 observations) | 1.05 | algorithm |
| Algorithmic RTGS | 0–1.0 | — |

## Primary Goal

**Shrink `dictionary.json` to zero.** Every entry in `dictionary.json` is a documented algorithm failure — a case where the syllable parser, weight tables, or variant generator produces the wrong top-1 result. The meta from the last calibration run shows 555 true gap entries and 176 reranking failures (right answer generated, wrong rank).

Progress is tracked by running `npm run calibrate:prune` after algorithm improvements and watching the entry count drop. See `TODO.md` for the full strategy (adding Wikidata/Wikipedia sources, weight tuning).

## Constraints

- Zero production dependencies — pure Node.js only
- ESM throughout (`"type": "module"`)
- Node.js v20+ required (uses `Intl.Segmenter` for word splitting)
- No TypeScript — plain JS with ESLint
- Built-in test runner only (`node --test`), no Jest/Mocha
- No mocking needed — all source modules are pure functions

## Testing conventions

Uses `node:test` + `node:assert/strict`. Pattern:

```js
import { describe, it } from 'node:test';
import assert from 'node:assert/strict';
```

Every bug fix needs a regression test that would have caught it. Tests use real Thai strings, not transliterated placeholders.
